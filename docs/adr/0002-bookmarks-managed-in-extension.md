# 新标签页成为书签栏的管理入口

---
status: accepted
date: 2026-11-01
supersedes: ADR-0001
---

ADR-0001 把书签定为只读镜像（浏览器管理、扩展只展示）。实际使用中发现用户从不打开书签管理器，整理动作希望直接在新标签页完成，只读约束反而制造了「还得回浏览器操作」的摩擦。故推翻只读约束：新标签页通过 `chrome.bookmarks` 的写 API（create/remove/move）直接管理书签栏——新建/重命名/删除分组、拖拽书签归组与调序、增删书签，全部实时写回浏览器书签栏。

代价：扩展从纯展示层变成读写层，UI 复杂度上升（拖拽交互）；写错操作的影响直接作用于真实书签（无撤销，靠操作克制 + 移动而非删除的默认倾向兜底）。展示侧不变的原则仍然保留：书签数据唯一来源始终是浏览器本身，扩展不自存任何书签数据。

## Considered Options

- 只读镜像（ADR-0001，被取代）：扩展简单可靠，但整理需切换到浏览器书签管理器
- 折中「先在浏览器整理、以后再说」：被否——用户明确扩展内更顺手，且写 API 成本不高
